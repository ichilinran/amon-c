# 引数補足と文末例外の設計

表記の規則は [RULES.md](../../RULES.md)、変換器の制限は [LIMITATIONS.md](../../LIMITATIONS.md) を参照してください。この資料は、現行の設定をどこで判断するか、その理由を説明します。

## 正本と処理の境界

- 既定の訳語は `src/vocabulary/vocabulary-current.js` が正本です。利用者の設定とは区別します。
- 引数補足と文末例外は `src/translation/usage-profiles.js` が正本です。実行時に使う設定だけを置きます。
- 標準関数として扱うかは、宣言・ヘッダなどの束縛情報で判断します。名前の綴りだけでは決めません。
- Cの式・呼出し・宣言の構造はClangの取得情報を用い、読みのための助詞で評価順序を変えません。

## 実行時の設定

| 設定 | 判断すること |
| --- | --- |
| `source` | 確認済みの標準名と設定を対応付ける |
| `reading_form` | 動詞形か名詞形か。利用者が訳語を変更しても属性は固定 |
| `parameters` | 各引数の名前・役割・前後に補う語 |
| `variadic`・`format_index`・`format_mode`・`wide` | 可変引数と書式の関係 |
| `content_suffix` | 書式ではなく表示内容として読むときの補足 |
| `conditional_omit` | NULLなど特定条件で補足を省く範囲 |
| `postfix` | 対応語を対象の後ろへ置く設定 |
| `statement_nari` | 文末のﾅﾘを省く条件と、その範囲 |

引数名や役割名は、設定の意味を保つために残します。実行処理が今直接参照しない識別用の項目まで一律に削除する方針ではありません。

## 読みの理由

### 表示内容と書式

表示内容だけのprintf・wprintfは、助詞なしで読めます。保存先や容量のある系列は、それらとの関係が分かるよう内容にｦを付けます。値を変換する書式にはﾃﾞを使い、幅・精度・書込先にはそれぞれの役割の語を使います。

書式を確認できず可変引数の役割が分からない場合は、書式と可変引数の補足を省き、固定引数の役割は保持します。値を別に渡さない表示内容の扱いが優先します。v系列は引数列の役割が固定なので、この省略を適用しません。

### 入れ子のｦ

動詞形の呼出し全体にｦを重ねると読みにくくなるため、外側のｦ単体だけを省きます。名詞形・利用者関数・計算式・明示キャストには同じ省略を適用しません。囲むだけの括弧では読みの型は変わりません。ﾆ・ｶﾗ・ｼﾞｮｳなどの役割や複合補足語は残します。

### 文末のﾅﾘ

動詞の終止形の後にﾅﾘを付けると「〜するなり（するとすぐ）」と読まれうるため、限られた関数と文脈に例外を設けます。動詞形というだけで全関数へ一般化しません。

| 関数 | 省略する範囲 |
| --- | --- |
| getchar | 引数0個の独立呼出しと直接の単純代入。呼出し全体を囲むだけの括弧も許す |
| abort | 引数0個の独立呼出し |
| raise・thrd_yield | 標準名に束縛された独立呼出し |

getcharの囲み括弧の許可を他の関数へ広げません。宣言・return・計算式・キャスト等の境界はRULESに記載しています。

## 設計情報の扱い

実行時データは、助詞・役割・条件の正本です。確認者の区分や過去の設定値を、現在の動作を決める入力にはしません。規則と実装が食い違う場合は、仕様の根拠と検査を照合してから変更箇所を判断します。文書の一般的な説明だけで、個別に確定した例外を取り消しません。
